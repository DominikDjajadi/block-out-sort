# Harder Co-Training Evaluation

The 3-seed baseline saturated quickly: most gains arrived in rounds 1-2, later
rounds usually tied the incumbent, and the frontier acceptance rate stayed near
3%.  That is a sign that the promotion pool is too easy for the current
protagonist and that longer runs alone will mostly measure ceiling effects.

## Generate a hard held-out pool

Create a new pool in a new path.  Do not reuse or overwrite
`promotion_pool_2028` or completed baseline run directories.

```powershell
python -m blocksort.cotraining.hard_eval_pool `
  --output ../data/eval/hard_pool_v1_20260723.jsonl `
  --total-count 120 `
  --seed 3107 `
  --rows 5 --cols 5 --color-count 3 `
  --density-range 0.30 0.45 `
  --mutation-budget-range 3 10 `
  --oracle-validation-budget 200000 `
  --oracle-validation-time-limit-seconds 10 `
  --designer-checkpoint runs/cotraining_multiseed_seed_2028/round_012/designer_attempts/attempt_001/best.pt `
  --checkpoint-every-attempts 25
```

Each JSONL record includes its generation bucket, seed, generation parameters,
oracle validation status, optional protagonist filter result, static level
signature, and canonical level hash. The `adversarial_designer_hard` bucket is
generated by the supplied designer checkpoint (and records its content hash);
the command rejects that bucket if no designer checkpoint is provided, rather
than silently substituting the random generator.

Generation progress is atomically checkpointed to
`<output>.partial.json` after every accepted record and periodically during
long rejection streaks. Re-running the exact command resumes automatically and
restores the deterministic random stream. The partial checkpoint is bound to
the semantic generation settings and the protagonist/designer checkpoint
content hashes, so changing an input is rejected instead of mixing two runs.
`--max-attempts-per-level` and `--checkpoint-every-attempts` may be increased
when resuming because they only control operational limits. The partial
checkpoint is removed only after the final JSONL has been written atomically.

Do not apply one protagonist solve-rate band to the default heterogeneous
five-bucket pool. The random, trained-designer, larger-board, additional-color,
and mutation-stress families have materially different solve-rate
distributions; a global band can erase entire buckets. Measure and stratify
difficulty after exact pool generation. The per-candidate oracle time limit
rejects pathological searches while preserving the requirement that every
accepted record has an exact solvability label.

Use the exact `designer_checkpoint` value from the source run's
`run_state.json`; co-training does not create a mutable `designer.pt` mirror.

Then create the immutable split manifest:

```powershell
python -m blocksort.eval_split `
  --eval-levels-dataset ../data/eval/hard_pool_v1_20260723.jsonl `
  --output ../data/eval/hard_pool_v1_20260723_split.json `
  --validation-count 60 `
  --split-seed 1729
```

```powershell
python -m blocksort.expert_iteration.budget_sweep `
  --checkpoint runs/cotraining_multiseed_seed_2028/best.pt `
  --eval-levels-dataset ../data/eval/hard_pool_v1_20260723.jsonl `
  --eval-split-manifest ../data/eval/hard_pool_v1_20260723_split.json `
  --split-role promotion_validation `
  --budgets 1 2 4 8 16 `
  --output runs/eval_sweeps/seed2028_hard_pool_validation.json `
  --device cpu
```

The summary reports total level count, classification-known count, coverage,
confirmed-optimal count, confirmed-optimal rate over total, confirmed-optimal
rate over classified examples, unknown count, exact-regret coverage, mean regret,
full-level solved count and solve rate over total, and bucket breakdowns when
bucket metadata is present.

The co-training loop evaluates only the 60-level `promotion_validation` split
for candidate promotion. It records the external `final_test` split as sealed
and does not load those states into per-round evaluation. Use validation for
all model, budget, and stopping-rule choices.

## One-seed pilot

Use a fresh output directory:

```powershell
python -m blocksort.cotraining.run `
  --protagonist-checkpoint runs/cotraining_multiseed_seed_2028/best.pt `
  --designer-checkpoint runs/cotraining_multiseed_seed_2028/round_012/designer_attempts/attempt_001/best.pt `
  --base-dataset ../data/training/pv_smoke.jsonl `
  --output-dir runs/cotraining_hard_pilot_v6_seed2035 `
  --rounds 5 `
  --levels-per-round 100 `
  --seed 2035 `
  --device cpu `
  --solve-rate-trials 5 `
  --frontier-min-solve-rate 0.20 `
  --frontier-max-solve-rate 0.70 `
  --min-frontier-acceptance-rate 0.10 `
  --frontier-imbalance-margin 0.05 `
  --frontier-backfill-target 10 `
  --min-fresh-levels-to-train 10 `
  --eval-levels-dataset ../data/eval/hard_pool_v1_20260723.jsonl `
  --eval-split-manifest ../data/eval/hard_pool_v1_20260723_split.json `
  --eval-split-seed 1729 `
  --eval-validation-count 60 `
  --eval-limit 60 `
  --promotion-metric weighted_budget_sweep_solve_rate `
  --promotion-budgets 4 8 16 `
  --promotion-budget-weights 0.2 0.3 0.5 `
  --promotion-margin 0.01 `
  --eval-budgets 1 2 4 8 16 `
  --exploratory-astar-time-limit-seconds 5 `
  --training-astar-time-limit-seconds 5 `
  --generation-checkpoint-interval 5 `
  --generation-progress-interval 5 `
  --designer-validation-episodes 8 `
  --designer-frontier-alignment-weight 1.0 `
  --epochs 3 `
  --learning-rate 0.0003
```

Generation now has two stages. First it checks validity and estimates the
protagonist solve rate for all candidates. Because `DesignerEnv` starts from a
solvable base and applies only reversible legal moves, every valid result has a
reverse-construction solvability proof. Exact A* scoring is therefore performed
only for strict-frontier and ranked-backfill levels that will actually enter the
round. A* is still tried first for optimal labels and structural metrics, but a
five-second cap records optimal cost as unknown instead of stalling or falsely
calling a construction-proven level impossible. An exact A* contradiction is
not overridden.

Generation progress is printed every five candidates and atomically saved to
`round_NNN/generation.partial.json`. Re-running the same command resumes that
stage deterministically; the partial file is bound to the run fingerprint,
round, curriculum, model content hashes, and solve-rate settings. It is removed
only after the round commits. Promotion-validation results are content-addressed
and reused when the exact same checkpoint, state set, budgets, and evaluation
semantics recur.

Training-state expansion is also bounded. For each accepted level, co-training
keeps the initial state, at most `--states-per-level` evenly spaced optimal-path
states, and `--states-per-level` random reachable deviations; it does not launch
the formerly multiplicative near-optimal walk sampler. With the default value
of four, that is at most nine candidates per accepted level before
deduplication. Exact analysis stops immediately when the root value is unknown,
and stops querying further successors after the first unknown successor,
because a complete exact policy label is already impossible and the neural
search fallback will be used. This prevents one per-search time limit from
silently multiplying across every legal action.

Designer PPO uses the same repeated noisy protagonist trials to measure whether
each valid, construction-proven level falls near the learning frontier. The
existing adversarial, structural, novelty, invalidity, and oracle-safety
components remain intact. A plateau-shaped alignment score is 1.0 inside the
0.20-0.70 frontier and tapers linearly toward zero at solve rates 0 and 1. Its
centered reward adjustment gives in-band levels a positive contribution and
gives the always-failed/always-solved extremes an equal negative contribution;
the adjustment is never applied unless the level is valid and oracle-solved or
construction-proven.

Designer checkpoints are evaluated on eight fixed validation levels after each
PPO update. Selection is lexicographic: strict in-band validation rate first,
mean tapered alignment second, and total validation reward only as the final
tie-breaker. This prevents a high adversarial-regret checkpoint with zero
frontier levels from beating a genuinely frontier-aligned checkpoint. Reports
include the full selection metric plus mean frontier solve rate, in-band rate,
alignment score, and evaluated count for training and validation episodes.

The extra repeated protagonist evaluations improve calibration but make this
pilot slower than v4. They remain bounded: five trials per
training/validation level, eight fixed designer-validation levels, and the
existing generation/A* limits.

## Budget-sweep designer calibration

Before another co-training pilot, freeze the v6 protagonist and warm-start from
the round-4 designer that produced v6's strongest subsequent frontier batch.
Train three independent designer seeds and require every seed to pass both its
fixed validation set and a separate 100-level generated holdout:

```powershell
python -m blocksort.cotraining.designer_calibration `
  --protagonist-checkpoint runs/cotraining_hard_pilot_v6_seed2035/best.pt `
  --designer-checkpoint runs/cotraining_hard_pilot_v6_seed2035/round_004/designer_attempts/attempt_001/best.pt `
  --output-dir runs/designer_budget_sweep_calibration_v1 `
  --seeds 2036 2037 2038 `
  --episodes 48 `
  --episodes-per-iter 12 `
  --validation-episodes 32 `
  --holdout-levels 100 `
  --rows 6 --cols 6 --color-count 3 `
  --density 0.40 `
  --mutation-budget 6 `
  --protagonist-simulations 220 `
  --solve-rate-trials 5 `
  --frontier-budget-min-ratio 0.25 `
  --frontier-budget-max-ratio 4.0 `
  --frontier-min-simulations 20 `
  --frontier-max-simulations 400 `
  --frontier-min-solve-rate 0.20 `
  --frontier-max-solve-rate 0.70 `
  --frontier-alignment-weight 1.0 `
  --frontier-dirichlet-alpha 0.5 `
  --frontier-dirichlet-weight 0.4 `
  --min-validation-frontier-rate 0.10 `
  --min-holdout-frontier-rate 0.10 `
  --astar-time-limit-seconds 5 `
  --device cpu
```

At a nominal budget of 220, the five trials use the deterministic geometric
schedule `[55, 90, 148, 244, 400]`. Each trial still has a stable per-level
noise seed, but the primary source of variation is now search effort. A level
that fails at low budgets and succeeds at high budgets receives an intermediate
solve rate even when fixed-budget behavior is otherwise deterministic.

The calibration is a `go` only when all three seeds achieve at least 10% strict
frontier yield on both the selected 32-level validation checkpoint and the
independent holdout, with zero invalid holdout levels. Each completed seed is
reused on restart; an interrupted seed is preserved and retried in a new
attempt directory. Do not start another protagonist pilot on a `no_go`.

Per-round `frontier_diagnostics.json`, plus cumulative
`frontier_diagnostics.json` and `frontier_diagnostics.csv`, distinguish
impossible/unsolved levels, too-easy levels, too-hard levels, duplicates, and
accepted frontier levels. `frontier_acceptance_rate` remains the strict
designer-quality measurement; `training_acceptance_rate` also includes the
nearest oracle-solvable ranked backfill. Exact scoring is a final acceptance
gate: any oracle-unsolved result is excluded from both protagonist and designer
replay even when reverse construction claimed solvability. The round report
records the rejected fingerprint, selection mode, oracle method, and whether
the result was an exact contradiction. Protagonist fine-tuning is skipped
unless the round supplies at least 10 new levels. Scale up to 3 seeds x 12
rounds only after the pilot shows non-saturated validation scores, materially
higher frontier acceptance, and budget-sweep promotion differences that are
not mostly ties.

Protagonist replay reserves 35% of each training sample for the active round,
25% for the previous two rounds, and 40% for older/base history. These shares
are configurable with `--replay-current-fraction`,
`--replay-recent-fraction`, `--replay-historical-fraction`, and
`--replay-recent-window`. If a bucket is empty, its quota is redistributed
proportionally across non-empty buckets. Within a small fresh bucket, every
distinct record is selected before records repeat to fill the reserved sample
share. Round reports include available, target, realized, and unique counts
plus the realized gradient mass for all three age buckets.

Replay source preferences are applied within each age bucket during the
deterministic draw and retained as policy-loss confidence weights after
selection. Consequently, configured age quotas describe sample composition;
round reports provide the realized gradient mass after source weighting. Exact
records retain scalar value supervision. Incomplete exact-path demonstrations
receive half policy weight by default
(`--exact-path-policy-confidence 0.5`) because their proved action does not
disprove other legal alternatives. Search-derived records retain
visit-policy supervision, while their bounded but uncertain scalar estimates
receive zero value-loss weight by default (`--search-value-loss-weight 0`).
Co-training also defaults to `--trainable-part policy_head`,
`--learning-rate 0.00003`, and `--epochs 1` so these small non-IID updates do
not move the shared trunk, value head, or their BatchNorm state.

## Continue from an externally confirmed protagonist

An independently confirmed checkpoint must start a new co-training output
directory. Do not replace a completed run's committed protagonist or edit its
`run_state.json`. Import the completed run's committed replay snapshots as
content-bound inputs:

```powershell
python -m blocksort.cotraining.run `
  --protagonist-checkpoint runs/incumbents/protagonist_policy_3e5_confirmed_v1/checkpoint.pt `
  --designer-checkpoint runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/round_002/designer_attempts/attempt_002/best.pt `
  --initial-base-split runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/splits.json `
  --initial-protagonist-replay runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/round_002/replay.jsonl `
  --initial-designer-replay runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/round_002/level_replay.jsonl `
  --base-dataset ../data/training/pv_smoke.jsonl `
  --output-dir runs/cotraining_hard_pilot_v9_policy_head_inherited_seed2046 `
  --rounds 1 `
  --trainable-part policy_head `
  --learning-rate 0.00003 `
  --epochs 1
```

The base-data split is inherited so previously trained base levels cannot move
into a new validation/test role merely because the new run has a different
random seed. Imported protagonist records are copied into the new run and
rebased to historical iteration zero, while their former iteration is retained
as `imported_generation_iteration` provenance. Imported designer levels seed
the new run's duplicate guard. All source hashes are part of the experiment
identity, frozen validation/final signatures are rejected, and resume reads the
new run's committed copies rather than mutable source paths.

## Diagnose successor-value ranking

Run this after a candidate improves scalar value calibration but fails the
MCTS promotion gate. It uses fully exact validation records to measure whether
the value head ranks optimal successor states ahead of worse legal
alternatives:

```powershell
python -m blocksort.cotraining.successor_ranking `
  --dataset ../data/training/pv_smoke.jsonl `
  --split-manifest runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/splits.json `
  --checkpoint incumbent=runs/cotraining_hard_pilot_v8_diverse_replay_seed2039/protagonist/initial.pt `
  --checkpoint depth_standard_a50=runs/diagnostics/v8_value_depth_sample_sweep_cuda_v1/candidates/depth_standard_a50.pt `
  --checkpoint depth_tail_a100=runs/diagnostics/v8_value_depth_sample_sweep_cuda_v1/candidates/depth_tail_a100.pt `
  --reference-name incumbent `
  --output-dir runs/diagnostics/v8_value_successor_ranking_v1 `
  --batch-size 512 `
  --device cuda
```

`top1_optimal_rate` reports how often the lowest predicted successor cost
belongs to an oracle-optimal action. `optimal_vs_suboptimal_pair_accuracy`
measures every optimal-versus-worse action pair, giving half credit to exact
prediction ties. `mean_selected_oracle_regret` reports the actual exact regret
of the value head's one-ply choice. Forced states and states where every legal
action is optimal are reported but excluded from the decision-state rate.
Terminal and immediate-deadlock successors use the same fixed costs as graph
search. The command is restricted to promotion-validation and never evaluates
the sealed final-test partition.

When the aggregate rankings remain stable but a few paired MCTS outcomes flip,
trace only those discordant validation levels:

```powershell
python -m blocksort.cotraining.search_trace `
  --audit-summary runs/diagnostics/v8_value_depth_sample_audit_v1/summary.json `
  --candidate-name depth_tail_a100 `
  --output-dir runs/diagnostics/v8_value_search_trace_v1 `
  --device cuda
```

The trace is content-bound to the source audit. It verifies the incumbent and
candidate checkpoint hashes, evaluation dataset and manifest hashes, audit
budgets, seed derivation, and promotion-validation membership before running.
For every discordant level and budget it records each simulation path, leaf
reason and value, root edge selected, visit counts, backed-up action costs,
next-selection scores, principal variation, and first discovered solution.
The command aborts if its final solved/unsolved result does not reproduce the
source audit.

## Run the final test once

After the checkpoint, budgets, and all reporting choices are locked, run:

```powershell
python -m blocksort.expert_iteration.budget_sweep `
  --checkpoint runs/cotraining_hard_pilot_v5_seed2034/best.pt `
  --eval-levels-dataset ../data/eval/hard_pool_v1_20260723.jsonl `
  --eval-split-manifest ../data/eval/hard_pool_v1_20260723_split.json `
  --split-role final_test `
  --budgets 1 2 4 8 16 `
  --output runs/eval_sweeps/LOCKED_seed2034_hard_pool_final_test.json `
  --device cpu
```

The final-test command requires a durable output file and refuses to overwrite
an existing final-test report. The report binds the result to the checkpoint
content hash and immutable split fingerprint. Do not rerun it under another
filename in response to the result; that would turn the final test into another
validation set.
